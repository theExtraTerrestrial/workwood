Round 21: an inbox of work, and a composer with room to write

The look follows from the first review: one calm neutral surface, no gradient, no glossy tiles, no cut-out tab. This draft records what is now settled and takes on the problem that came out of it: the composer is filling up.

Settled

  • The sidebar is an inbox of work, grouped by project. Done sessions leave it; search finds them.
  • Sessions nobody touches clear themselves, and any new work in a done session brings it back.
  • Limits sit in a quiet line under the message box, for the profile the session is running on. The same line switches profile and carries the conversation on.
  • Model and effort are one control. Skills leave the side panel and live in the composer.

Still open: where each control sits in the composer (part three), and two small questions at the end.

Part one: the sidebar as an inbox

A session is in the sidebar because it still needs something: from the agent, or from you. When it is finished with, it leaves. The sidebar should usually be short, and an empty one means you are done.

WorkingThe agent is on it. Nothing for you to do.
1 questionIt stopped to ask, or wants approval. The only amber in the sidebar.
Finished, unreadThe turn ended and you have not looked. Bold title and a dot, like unread mail.
OpenYou have read it but not closed it. Quiet. Stays until you decide.
✓ DoneYou marked it done, or it sat untouched for a week. It leaves the sidebar; search finds it.
  • Marking done is one press: a Done button in the session's header, the same button when you hover a row, or Ctrl+D. It replaces today's Archive, which is the same idea under a filing-cabinet name. After marking done, the next session that needs you opens, so you can work down the list.
  • Untouched sessions clear themselves. An open session with no activity for 7 days is treated as done, without you doing anything. Sessions that are working, waiting for you, or unread never clear this way. The number of days is a setting.
  • Done is never final. Any new work in a done session, a message from you here or activity from a terminal, brings it back into the inbox. Nothing is deleted.
  • Finding older work is search (Ctrl+K), which looks through every session, done or not. A single "Done" row at the bottom of the sidebar opens the same list with nothing typed, newest first.
  • Grouped by project, most recently active project first, and newest first within it, so the latest work on a project is always its top row. A project with nothing open is not listed. Profiles no longer shape the list: their limits move to the composer (part two).

Finding older sessions

Search covers titles and what was said. Done sessions open read-ready; writing in one reopens it.

Part two: limits, and switching profile

One line of small grey text under the message box, always in the same place, as quiet as placeholder text. It shows the profile this conversation is running on and that profile's 5-hour and 7-day use. It never asks for attention unless something has changed that you need to act on.

Part three: a composer with room to write

Counting everything now asked of the composer: attach, skills, model and effort, context, dictate, send, the limits, and on a new session the project and profile. Put all of that in the box and the place where you write becomes the smallest thing in it. The proposal is one rule: the box holds your message and what you do to it; the line under it holds the conditions it runs under.

Questions for you

  • P or Q for the composer? P is my recommendation and it changes one thing you had agreed to, so it is yours to call.
  • Seven days before a quiet session clears itself? It would be a setting either way; this is only the starting value.
  • Sessions started in a terminal, outside Workwood: my suggestion is that they appear only while they are running or waiting, so the inbox stays yours.
