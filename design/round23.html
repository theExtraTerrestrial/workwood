Round 23: what keeps running — background commands, monitors and agents

Round 22 made each step readable while it runs. Some work doesn't fit in one step: a dev server the agent started in the background, a monitor watching a log for the line it's waiting for, an agent sent off to search the code with its own dozen steps. Claude Code shows all three — a list of background shells you can open and kill, monitors with their events, sub-agents with their tool calls, token count and clock. In Workwood today a background command is a tag on a finished step, a sub-agent is one line, and a monitor doesn't appear at all. Once the turn ends, nothing says anything is still running.

Settled in round 22

  • Steps are a rail with past-tense headings and their time on the right. Each command sits in its own escaped code block. Output stays collapsed until you ask for it, except on a failure.
  • The steps of the running turn are open and close themselves when it ends. A running command has a live clock and its own Stop.

The whole picture

The turn has ended, but the agent left three things running: a dev server, a monitor on the test watcher, and an agent still reading the code. They gather in a tray just above the message box, where your eye already is. Closed, it's one line naming what's running. Open, it lists each task with its clock, its last line of output and a Stop. Output opens the task's live output in the side panel, next to the preview and changes. The session in the sidebar shows 3 running where it would otherwise just show its time.

  • The tray is there only while something runs, and it outlives the turn. When the last task ends, it goes.

Agents: their own steps, inside their step

AAn agent's step holds a small rail of its ownRecommended

While it runs, an agent's step shows its type, its task, a live clock, and a box with its last three steps, its step count and the tokens it has used. The box is tinted violet so it can't be mistaken for the main agent's steps. Earlier steps fold into “11 earlier steps”, which opens them all. When it finishes, the box keeps the count and its report: the answer it gave back, collapsed to a few lines.

Monitors: something watching for you

A monitor runs a command, or opens a socket, and every line it prints is an event for the agent. Its step says Watching and what it watches, and shows the newest events with their times; the full list opens from the tray. A new event also leaves a short note in the thread, because it may be the reason the agent wakes up and starts a turn on its own. Without that note, the turn would seem to start from nowhere.

What the service has to work with

  • task_started gives each task an id, its tool call, its kind (shell, agent, monitor) and whether it runs in the background. task_updated and task_notification give its status, end time, output file and summary. background_tasks_changed is the full set of what's running, sent whenever it changes, so the tray can be rebuilt from it rather than pieced together.
  • task_progress gives an agent's tokens, step count, time and last tool. Its own steps arrive as ordinary messages with parent_tool_use_id set to the agent's step, which the service drops today.
  • stopTask(id) stops any of them. A shell's live output comes from its output_file, read from the end.
  • The catch: Workwood ends the SDK query when the turn ends, and the Claude Code process goes with it, so background tasks die with it. To keep a dev server running, the service must keep the session's query open while its tasks run, and close it when the last one ends or you stop them.

Open questions

  • Should the tray start open or closed? Open shows more at a glance; closed keeps the message box where it was.
  • When a background shell exits non-zero after the turn, should Workwood mark the session unread, like a finished reply?
  • Should closing the window (or quitting the service) stop background tasks, or ask first when something is running?
  • Should an agent's whole report be in its step, or only a few lines, with the rest left to the main agent's reply?
