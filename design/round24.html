Round 24: new messages while you're scrolled up

While the agent works, the thread follows it only if you're already at the bottom. Scroll up to re-read something and the thread stays put, which is right, but then nothing tells you a reply has arrived below. This round adds a mark that says how many new messages are waiting and takes you to them with one click. The three options below are live: each thread opens scrolled up with three unread replies. Scroll them, click the mark, and use the buttons under each one to make the agent say more.

The same in every option

  • A message is a reply, a question or a plan. Steps (commands, edits, searches) don't raise the count. If only steps have arrived, the mark shows a small live dot instead of a number.
  • A “New” line is drawn in the thread above the first message you haven't seen, so you can find your place after you jump.
  • The count goes down as you read. A message stops being new once its first line has scrolled into view. At the bottom, the mark disappears.
  • The thread never moves on its own while you're scrolled up. Sending a message still takes you to the bottom, as today.

What the service needs

  • Nothing. This is all in the window. Items already arrive one by one on the event stream, each with a number and a kind, so the window can tell a reply from a step.
  • The thread already follows only when you're within 160px of the bottom. The mark uses the same line: beyond it, arriving messages are counted instead of followed.
  • A reply that is still being written updates the same item, so it counts once.
  • The count lives in the window only. It isn't saved, and it resets when you switch sessions.

Open questions

  • Should a click land on the first new message (so you read them in order) or go straight to the bottom? The mockup lands on the first new one.
  • Should the mark show as a plain arrow when you're scrolled up with nothing new, or only once a message arrives?
  • Should the “New” line stay in the thread after you've read past it, or clear once you reach the bottom?
  • Should a finished turn count as something new on its own (“Done · 3 files changed”), or only its replies?
