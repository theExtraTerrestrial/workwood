The four variants

  • A · Card (recommended). One line, how many changes, Restart or Later. Hovering “5 changes” lists their titles.
  • B · Strip. A single tinted row, the quietest that still asks. No close button: Later hides it until the next start.
  • C · What changed. The card lists the newest commit titles, so you can tell if it is worth restarting now.
  • D · Just a dot. Nothing pops up; a dot on the gear, and the restart sits at the top of Settings. For people who never want to be asked.
Under the hood
  • On start: the service runs git fetch origin in the app folder, then git rev-list --count HEAD..@{u}. Zero → nothing shown. Titles come from git log --format=%s HEAD..@{u}.
  • Restart: git pull --ff-only; if package-lock.json changed, npm install; then Electron's app.relaunch() + app.exit(). Sessions are Claude Code sessions on disk, so they come back as they were.
  • Can't update: local edits that block the pull, a branch other than main, or no network. The fetch failing silently (offline) shows nothing at all.
  • Agents working: a restart would cut running turns, so the button says so and asks once more.

Open questions

  1. Check only on start, or also every few hours while the app stays open? Workwood tends to run all day.
  2. Agents working: warn and restart anyway (shown), or wait and restart by itself once they're all idle?
  3. Windows copy (%LOCALAPPDATA%\Workwood, from npm run shortcut): should Restart also redo that copy, or only show “run npm run shortcut again” there?
  4. Local edits in the app folder (you develop Workwood in it): skip the check entirely when the tree is dirty, or show “Can't update” as drawn?
