Under the hood
  • The service keeps listening only on 127.0.0.1 in WSL. The Windows window, which already reaches it as localhost, opens one port on the home network and passes the connection through untouched. TLS ends in the service, so the Windows side never sees content. That's why it works only while Workwood is open, and why Windows asks once (its firewall).
  • Workwood makes its own certificate authority once and keeps it in its settings folder. The phone trusts that authority, not one address, so Workwood can quietly reissue the server certificate when the PC's address changes, without asking again. The authority signs only Workwood's own addresses.
  • The QR code opens a plain-HTTP setup page that serves only the certificate and these steps, nothing private. The one-time key in the code is redeemed only over HTTPS once the phone trusts the PC, and becomes that phone's own revocable key.
  • Notifications are Web Push: encrypted on the PC, delivered by Apple's or Google's push service, which sees neither the text nor which session.
  • Later, other routes for away from home (WireGuard, Tailscale) slot in front of the same port without changing the phone side.

Open questions

  1. Phone access works only while the Workwood window is open on the PC. Is that fine, or should it keep working with the window closed? That would need a one-time WSL network setting and a WSL restart.
  2. Name shown for the PC: the Windows computer name (DESKTOP-AX), or something you choose in Settings?
